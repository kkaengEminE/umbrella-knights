# 세 우산 기사단 — 최소 프레임 제작 명세 v2

## 제작 원칙
많이 그리기보다 준비·타격·회복이 읽히는 최소 자세를 만든다. 같은 자세를 오래 보여 주는 것은 duration으로 처리하고, 중복 이미지를 만들지 않는다. 추가 프레임은 실제 플레이에서 끊겨 보이는 구간에만 넣는다.
대화와 설정의 승인된 원화는 유지한다. 월드와 전투를 픽셀로 바꾸는 작업은 단계적으로 진행한다.

## 지금 사용할 샘플
설 대기 2장(각450ms), 달리기 4장(각140ms), 약공격 3장(85/110/85ms).
약공격은 준비 → 타격 → 회복. 시작85ms에 한 번 피해를 발생시키며 전체280ms는 유지한다. 달리기 한 사이클도560ms로 유지하므로 프레임 축소가 이동 속도나 공격 속도 변경을 뜻하지 않는다.
기존 AI 원본에서 필요한 자세를 선택했다. 원본 PNG에는 미사용 프레임이 남아 있으므로 다운로드 용량이 줄었다고 주장하지 않는다. 현재 목표는 신규 원화 제작량과 동작 복잡도를 줄이는 것이다. 최종 원화가 정해지면 사용 프레임만 묶어 배포용 아틀라스로 만든다.
sprite-lab.html에서 재생·정지·한 프레임·좌우 반전·타격 구간을 확인한다. 게임의 ?pixel=1은 설의 세 동작만 시험하는 프로토타입이다. 미제작 동작·동료·배경은 기존 그래픽을 유지한다.

## 캐릭터별 최소 동작
|동작|타임라인 프레임|제작 방식|
|---|---:|---|
|대기|2|호흡 두 자세|
|달리기|4|발 뻗기·모으기·반대 발·복귀|
|점프 준비 / 상승 / 하강 / 착지|각1|물리 이동과 착지 반동으로 보완|
|2단 점프|2|웅크림·펴기|
|대시|2|낮춤·복귀, 잔상은 엔진|
|약공격 / 공중 약공격|각3|준비·타격·회복, 상체 재사용|
|강공격|5|준비2·타격1·회복2|
|공중 강공격|4|준비·하강타격·회복|
|막기 시작 / 유지 / 해제 / 방어성공|각1|해제는 역재생, 성공은 위치 반동|
|피격|2|고유 자세와 명도 변화|
|탈진|3|휘청·무릎·쓰러짐|
|우산 펴기 / 접기|각2|접기는 역재생|

프레임 수는 타임라인 슬롯 수이며 신규 원화 수와 다르다. 공통 자세 재사용으로 실제 제작량은 더 줄인다. 정확한 시간과 이벤트 인덱스는 assets/pixel/animation-plan.json을 기준으로 한다.

## 스킬 9종
설의 서리 베기 / 무영의 그림자 일섬 / 홍아의 가시 덩굴: 시전3장.
설의 빙결 파동 / 무영의 밤의 장막 / 홍아의 장미의 방패: 시전4장.
설의 빙하의 심장 / 무영의 월식 / 홍아의 가시 정원: 시전5장.
각 프레임120ms 초안. 발사 이벤트는 중간 타격 자세에서 발생한다. 기존 스킬 밸런스를 이 명세만으로 바꾸지 않으며, 실제 통합 시 판정과 쿨타임을 맞춘다.
효과는 생성3·유지2·소멸3장을 상한으로 한다. 이동·크기·알파는 엔진으로 처리하고 거리마다 새 그림을 만들지 않는다. 같은 결정·가시 조각을 배치·반전해 재사용한다. 무영의 안개는 블러 대신 검은 픽셀 덩어리와 디더링으로 표현한다.
발사 전 피격은 시전 취소, 발사 후 투사체 유지, 쿨타임은 발사 순간 시작하는 규칙을 목표로 한다. 아직 구현되지 않은 스킬 모션은 JSON에 planned로 표기한다.

## 규격과 판정
128×128 논리 픽셀 셀, 발 기준점(64,100), 인물 약64px. 오른쪽을 기본 제작하고 왼쪽은 발 기준점 주위 반전한다. 정수 배율·최근접 보간, 팔레트20~24색 목표.
AI 샘플은 정확한128px 셀이 아니므로 pixel-animation.js에 실제 소스 사각형과 기준점을 기록한다. 최종 원화는 픽셀 그리드와 팔레트를 정리해야 한다.
몸·우산·참격·스킬 효과·바닥 효과 분리. 현재 샘플 약공격은 무기가 포함되어 별도 우산 렌더를 끈다. 몸의 이동은 물리 엔진이 담당한다.
동일 공격의 동일 대상 중복 피해 금지. 프레임이 건너뛰어도 활성 시점 이벤트는 발생해야 한다. 일시정지는 타임라인도 정지, 교대·탈진은 예약 공격 취소. 날씨 우산 전환은 공격 종료 후 처리한다.
우선순위: 탈진 > 피격 > 방어 반동 > 스킬 > 공격 > 대시 > 점프 > 방어 > 이동 > 대기.

## 배경·몬스터 최소 제작
첫 지역만 완성해 검증한 뒤 늘린다. 32px 숲 타일: 지면 상단·중간·끝·플랫폼·모서리. 원경·중경·전경 분리. 물·풀은2프레임 또는 정지 타일로 시작한다.
잔향1종: 대기2·이동4·공격3·피격1·소멸3. 공격 준비 자세를 길게 보여 주어 회피 기회를 준다. 몸 접촉은 피해 없음.
보스1종: 대기2·이동4·공격 패턴당5·피격1·패배4에서 시작. 특수 패턴에만 프레임 추가.
금화4·경험치2, 사과·고기 정지 이미지. 비·착지 먼지·대시 잔상은 작은 공통 파티클을 재사용한다.

## 다음 단계
설의 최소 샘플 검수 → 점프·대시·강공격·방어 → 설 스킬3종 → 같은 기준으로 무영·홍아 → 숲과 잔향1종 → 보스.
유사한 달리기 자세는 향후 발 접지 차이가 더 뚜렷한 원화로 교체한다. 프레임 수만 늘려 해결하지 않는다. 이번 결과는 최적화한 제작 계획과 검증용 샘플이며 전체 픽셀 전환 완료가 아니다.

## 원화 일치 수정 — 설 v2
상세 캐릭터를 새로 단순화하는 대신 승인 원화의 PIXEL STUDY를 복장 기준으로 삼는다. 청색 어깨 외투, 겹친 허리 벨트와 파우치, 짧은 결정 장식, 장식 부츠를 유지한다.
seol-study-v2.png는 대기2·달리기4·약공격3 자세를 포함한 수정 시안이다. 이전 seol-movement.png와 seol-light.png는 비교용 구버전이며 런타임에서는 불러오지 않는다. 픽셀 제작실과 ?pixel=1 테스트에서 새 시트를 사용한다. 무영·홍아도 각자의 원화 PIXEL STUDY를 같은 방식으로 기준 삼는다.

## 설 추가 동작 v3 — 실제 구현
추가 원화9자세를 공유한다. 강공격3프레임(200/160/190ms), 점프 상승·하강 각1, 대시2, 피격2, 스킬별3프레임. 강공격은200ms, 스킬은120/180/240ms 시점에 피해가 발생한다. 발사 전 피격 시 취소되고 쿨타임을 소모하지 않는다.
점프·대시의 잔상은 이전 월드 좌표의 자세를 짧게 남기며 공격 궤적은3px 그리드의 픽셀 점으로 그린다. 서리 베기는 얼음 칼날, 빙결 파동은 지면 결정, 빙하의 심장은 방사형 결정 효과를 사용한다. 추가 효과 PNG를 양산하지 않는다.
sprite-lab.html에서 모든 동작과 효과를 바로 재생할 수 있다. ?pixel=1 게임 테스트의 설에 실제 연결한다. 스킬 슬롯·해금·쿨타임은 기존 게임 규칙을 유지한다. 무영·홍아와 방어·탈진 전용 픽셀 시트는 아직 제작 전이다.

## 동료 확장 v4
무영·홍아도 각18자세 시트를 사용한다. 대기2·달리기4·약공격3·강공격3·점프2·대시2·피격2·각 스킬3단계이며 회복/시전 자세를 재사용하므로 타임라인 프레임 수만큼 새 원화를 만들지 않는다.
캐릭터 선택: PartyPixel.forHero(0/1/2). 제작실과 ?pixel=1 게임에서 사용한다. 효과와 잔상은 발생 당시 hero를 저장하여 교대 후 다른 캐릭터로 바뀌지 않는다.
무영: 그림자 일섬·밤의 장막·월식. 홍아: 가시 덩굴·장미의 방패·가시 정원. 무영의 순간이동 및 홍아의 보호/회복은 기존 규칙을 유지한다.
일반 게임 경로의 기본 그래픽과 방어·탈진 전용 시트는 이번 범위에 포함되지 않는다.

## 방어·탈진 및 환경 시안
세 캐릭터별 방어 1장·탈진 1장을 party-guard-down.png에 추가. 방어 성공은 방어 자세에 120ms 위치 반동을 적용하며 별도 프레임을 늘리지 않는다. 픽셀 테스트에서 숲의 다층 배경, 지면·발판 타일, 종탑·마을, 비, 일반 적·보스의 도형 기반 픽셀 표현을 사용한다. 최종 환경 원화가 아닌 플레이 가능한 프로토타입이다.
